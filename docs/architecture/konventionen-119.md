# Architektur-Karte: Konventionen §5.119

Teil von [architecture.md](../architecture.md), §5 „Konventionen im Einzelnen“; Nummern unverändert. Index: [architecture.md](../architecture.md#konventionen-im-einzelnen).

119. **Geheimnisse teilen (v0.35.0, Owner-Entscheidungen 2026-11-01)** (Plan [plan-v035-secret-sharing.md](../plan-v035-secret-sharing.md); Vertrag `packages/domain/src/secret-share.ts`; cms `api/secret-share/**`, `utils/secret-shares.ts`, `utils/secret-crypto.ts`, `cron/secret-share-janitor.ts`, `bootstrap/secret-share-admin-closure.ts`, `middlewares/secret-shares-no-store.ts`; Web `/secrets`, `/secrets/new`, `/secrets/[id]`, `lib/secret-actions.ts`, `lib/secret-share-errors.ts`, `lib/loaders/secrets.ts`, `components/secrets/**`; Betrieb `infra/restore-db.sh` (Purge), `infra/diagnostics/secret-shares-rollback.sql`; Sicherheitsmodell [security.md „Secret sharing“](../security.md#secret-sharing)):
    - **Vertrag zuerst, eingefroren.** Tabellen- und Spaltennamen, Indizes, das Krypto-Format (HKDF-SHA256 aus `ENCRYPTION_KEY`, AES-256-GCM, Umschlag `v1.<nonce>.<ct‖tag>`, AAD mit documentId, beiden IDs und Ablauf) und die Ablehnungen (`SECRET_SHARE_REFUSALS`: Status nach Ursache, `unavailable` als 409/503/410) liegen in `@sinnlos/domain`. Ops-SQL und Web benennen sie von dort; eine Änderung bricht gespeicherte Umschläge oder Ops-Skripte.
    - **Nur der Umschlag erreicht Persistenz oder Abonnenten.** Klartext existiert nur in den Create- und Reveal-Handlern des cms und im Ergebnis der Reveal-Server-Action des Webs. Zugriff nur über `strapi.db.query`/knex in den Share-Transaktionen; kein Document Service, keine Relationen (skalare `senderId`/`recipientId`), daher explizite Abfragen für Export, Anonymisierung und Waisen.
    - **Höchstens einmal.** Locks in fester Reihenfolge (Verzeichnis-Lock, beide User-Zeilen aufsteigend, Share-Zeile), frische Aufrufer-Prüfung unter den Locks (Konto, Sperre, Rolle, `tv`, MFA-Entscheidung), bedingtes Update `pending → retrieved` mit genau einer Zeile, Text erst nach bestätigtem COMMIT (`executionPromise` der knex-Transaktion nach der äußersten). Jeder Zweifel antwortet `busy` ohne Text und setzt nie auf `pending` zurück; ein `busy`-Create kann den Share trotzdem angelegt haben.
    - **Admin-Panel zu.** Jeder Boot entfernt alle Content-Manager-Rechte auf den Typ (Strapis Super-Admin-Reset gibt `read` bei jedem Boot neu, daher die Zeile `[admin-permissions] removed 1 …` bei jedem Boot); dazu verweigert die gewrappte `permission-checker`-Factory des Content Managers den Typ immer, Preview per UID.
    - **Janitor jede Minute, unabhängig von `FEATURES_OFF`** (Löschung): abgelaufen → `expired`, nicht berechtigte Partei → `cancelled` (je Umschlag weg, Benachrichtigung weg), Waisen in jedem Zustand gelöscht, beendete nach 7 Tagen gelöscht. Ein Restore schließt alle eingespielten Shares im cms-Schema (`restore-db.sh apply`), der Rollback auf v0.34 löscht alle per SQL.
    - **Web: der Text nur im Client-State.** Klick → Server Action → State der Reveal-Komponente; kein `refresh()`, keine Server-Props; geleert bei `pagehide` und Unmount, späte Ergebnisse verworfen (Generationszähler). Eigener Fehler-Wrapper loggt nur Status und Code (`runCmsAction` loggte den Upstream-Body); `logging.serverFunctions: false`. `Cache-Control: private, no-store` auf `/secrets/:path*`. Plausible wird bei eingeschaltetem Modul nicht gerendert, und ein Dokument, das Plausible schon geladen hat (Tab von vor dem Einschalten), lädt vor Eingabe oder Anzeige neu (`components/secrets/clean-document.ts`).
    - **Tests:** Integration auf SQLite und Postgres 16 (Locks, verlorenes COMMIT, Rennen, Content-Manager-Routen nach erneuter Freigabe, Sentinel), Restore-Purge mit Stubs und echtem Postgres (auch ein Schema in Anführungszeichen), Browser-Tests `secret-sharing` und der eigene Live-Lauf `secret-live` (`run.mjs --live`).
